# Agent Guidance

## Open-issue contextualization

Before beginning substantive work in this repository, enumerate and inspect every open GitHub issue visible to the current identity. Do this before deciding which issues are relevant; relevance is an outcome of the review, not a filter for it. Treat this as contextualization, not authorization to begin backlog work.

Report a concise assessment of the open-issue backlog, identifying candidates related to the current task and any duplicate, blocked, stale, or dependency-linked work. Consider each issue's scope, labels, status, blockers, dependencies, duplication risk, and whether it is within the requesting user's authority.

Do not automatically claim, modify, implement, close, comment on, or otherwise act on an issue solely because it appears in the review. A user-directed task remains the highest priority. Begin additional issue work only after explicit authorization.

When access is limited, enumerate and inspect every issue and metadata item the current identity is permitted to view. Do not copy private issue content into broader agent context.
