# Agent Guidance

## Open-issue contextualization

Before beginning substantive work in this repository, inspect the open GitHub issues that are relevant to the current task or repository area. Treat this as contextualization, not authorization to begin backlog work.

Report a concise set of relevant issue candidates, or state that none are relevant. Consider each candidate's scope, labels, status, blockers, dependencies, duplication risk, and whether it is within the requesting user's authority.

Do not automatically claim, modify, implement, close, comment on, or otherwise act on an issue solely because it appears relevant. A user-directed task remains the highest priority. Begin additional issue work only after explicit authorization.

When access is limited, inspect only issues and metadata the current identity is permitted to view. Do not copy private issue content into broader agent context.
